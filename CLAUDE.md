# Revflare

Self-hosted in-app purchase / subscription revenue tracker on Cloudflare (replaces RevenueCat's dashboard): Worker (Hono) in `worker/`, React web app in `src/`, iOS app in `ios/` (SwiftUI, XcodeGen), CLI in `cli/`, agent skill in `skills/revflare/`, iOS SDK (RevflareKit: Apple Ads attribution, purchases, Meta ids for the Conversions API in `worker/lib/meta.ts`) in `sdk/ios/` with its integration skill in `skills/revflarekit/` (update the skill and `sdk/ios/README.md` together whenever RevflareKit changes). Optional private working notes go in the git-ignored `PROGRESS.local.md`.

- `npm run dev` runs Vite with the Cloudflare plugin (local Worker, Durable Object database, R2, Workflows). With `DEV_SEED=true` in `.dev.vars`, `POST /api/v1/dev/seed` fills the current workspace with a year of synthetic sales. `npm test` runs vitest (node unit tests + `test/workers/` integration tests in workerd). `npm run typecheck` before committing.
- Database: SQLite inside one Durable Object (`RevflareDatabase`, `worker/lib/db.ts`) behind a D1-like interface (`c.var.db` / `getDb(env)`): the account's D1 quota is full. Binding a D1 database as `D1` switches without code changes. Durable Object SQLite binds **at most 100 parameters per statement**. Heavy work (JWS verification, Apple/RevenueCat syncs, metrics) runs inside the object via `defineDbFunction` / `dbCall` (30 s CPU there vs ~10 ms in the Worker on the Free plan); inside the object, nested database functions run in-process.
- Free plan database budget: 5M rows read / 100k rows written a day (reset 00:00 UTC; over it every request fails until the reset). Rollups are incremental (`rollup_queue.from_day`) and write only changed `daily_metrics` rows; `workspace_daily` holds whole-workspace totals; reads go through a versioned cache (`data_version:<ws>`); background work (backfills, imports, history syncs) is metered and capped per day (`worker/lib/budget.ts`); `test/workers/budget.test.ts` guards the cost of a sale and of a cached read. Never scan `transactions` in recurring work.
- After `wrangler deploy` the Worker switches at once but the database object can keep running the previous code for a few minutes (until it restarts): check database-side changes after a short wait.
- Schema changes: add `migrations/000N_*.sql`; `worker/lib/migrate.ts` applies them when the object starts.
- Apple is the source of truth: every sale is keyed by Apple's transaction id. App Store Server Notifications V2 arrive at `POST /apple/notifications/:key`; JWS chains are verified to the pinned Apple Root CA G3 (`worker/apple/jws.ts`; tests use the chain in `test/fixtures/apple-test-chain.json`, made by `scripts/make-test-chain.sh`). Apps whose notification URL points elsewhere (RevenueCat) are polled through Notification History; customers are completed with Transaction History. Never replace a notification URL that points elsewhere without the user's consent (`/apps/:id/connect-notifications` exists for that).
- App Store acquisition: Apple's App Analytics reports (`worker/apple/analytics.ts`: one ONGOING report request per app, needs an Admin key; daily instances → gzip TSV segments → `acquisition_daily`, Standard and Detailed rows kept apart; reads in `worker/lib/acquisition.ts`). Reports (Sales and Trends, App Analytics) use the optional `appstore_reports` credential before `appstore_connect` (`reportCredentials`).
- Ledger (`worker/lib/ledger.ts`) → `transactions` / `subscriptions` / `customers`; rollups (`worker/lib/rollup.ts`) rebuild `daily_metrics` per app (MRR and actives by sweeping paid periods; movement = new / expansion / contraction / churn / reactivation). Reads (`worker/lib/metrics.ts`) rebuild queued apps first, so they are never stale. Money is stored in USD (`fx_rates`), shown in the workspace currency.
- Multi-tenant: every handler scopes by `wsId(c)` and guards with `requirePermission("read" | "manage" | "members" | "delete")` (`worker/lib/auth.ts`). Auth: web session cookie, iOS device token (`rfd_...`, from a QR pairing code or email/password), workspace API keys (`rf_...`, CLI/MCP/Adsflare).
- REST contract: `/api/v1`, types in `shared/types.ts` (mirrored in `ios/Revflare/Core/Models.swift` and `cli/src/types.ts`), docs in `docs/api.md`. Keep the MCP tools (`worker/routes/mcp.ts`), the CLI and the skill in sync with it.
- One cron trigger (`*/5`, the account's 5 are shared): `worker/lib/cron.ts` picks work by slot and stays under the subrequest limit. Long imports are Workflows (`worker/workflow.ts`), one bounded database call per step.
- Web apps (`platform = 'web'`) sell through Polar: signed webhooks at `POST /polar/webhooks/:key` → ledger (`worker/polar/ingest.ts`, store/source `polar`, docs/polar.md). Apple-only work selects `platform = 'ios'`.
- Push: APNs token auth (`worker/lib/push.ts`), texts are localized on the device (`loc-key`s in `ios/Revflare/Resources/*.lproj/Localizable.strings`).
- Personal deploy config lives in the git-ignored `wrangler.local.jsonc` (custom domain, `PUBLIC_URL`, APNs vars; template `wrangler.local.example.jsonc`); personal iOS signing (team, bundle id) in the git-ignored `ios/Local.xcconfig`. Secrets: `APNS_PRIVATE_KEY`, optional `SECRET_KEY`, `SETUP_TOKEN`. Never commit personal domains, ids or real revenue: tests and demo data use synthetic values (`com.example.*`).
- Releases: Conventional Commits, release-please (server `v*`, CLI `cli-v*`), see `docs/RELEASING.md`. Copies of the repo update via `.github/workflows/revflare-update.yml` + `scripts/revflare-update.sh` (test: `bash scripts/test-revflare-update.sh`).
